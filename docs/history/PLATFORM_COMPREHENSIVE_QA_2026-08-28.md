# تقرير الفحص الشامل لمنصة ذي قار الرقمية

**تاريخ الفحص:** 28 أغسطس 2026  
**نطاق النسخة المفحوصة:** نسخة محلية مبنية من الفرع `main` ونسخة الإنتاج المنشورة بعد تحسين شاشة فيديو الوجه، مع تحقق من الصحة والحماية والحزمة النهائية.  
**منهج الفحص:** جميع الطلبات التي تنشئ بيانات أو وسائط استُخدمت معها قاعدة بيانات ووسائط مؤقتة معزولة وبيانات صناعية فقط. لم تُنشأ معاملات أو مرفقات أو رسائل تحقق حقيقية في الإنتاج.

## النتيجة التنفيذية

اجتازت الوظائف الأساسية ومسارات الخدمات والحساب والصلاحيات والأرشفة وفحص الهاتف الاختبارات المحددة. لم يظهر خطأ بناء أو خطأ تشغيل JavaScript أو مسار خدمة مفقود. كما أن نسخة الإنتاج أجابت عن فحص الصحة بحالة `200`، ورفضت نقاط المواطن والإدارة الحساسة عند غياب الجلسة بحالة `401`.

تحسين شاشة فيديو الوجه الذي طلبته أخيراً اجتاز الفحص محلياً ثم نُشر إلى Railway ضمن الالتزام `0113224`. طابقت عملية التحقق اللاحقة أسماء حزم JavaScript وCSS المنشورة مع البناء المحلي، ووجدت عبارات التعليمات المتتابعة في الحزمة المنشورة. بقيت بقية وظائف الموقع سليمة أثناء الفحص.

| المجال | النتيجة | ما تم التحقق منه |
|---|---|---|
| البناء والأنواع | ناجح | `pnpm build` اكتمل بنجاح وTypeScript لم يعرض أخطاء. |
| فحص الشفرة | ناجح مع تحذيرات غير مانعة | `pnpm lint` أعطى `0` أخطاء و`13` تحذيراً غير مانع، أغلبها تحسينات React لاحقة وليست أعطالاً تشغيلية. |
| سلامة التغييرات | ناجح | `git diff --check` لم يجد مسافات خاطئة أو ترقيماً غير سليم. |
| الصحة في الإنتاج | ناجح | `/api/health` رجع `200` وباستجابة API سليمة. |
| تجربة الهاتف | ناجح | الصفحة الرئيسية والدخول والتسجيل والخدمة المحلية والوطنية والتحقق لم تسجل تمريراً أفقياً أو صفحة مفقودة. |

## الخدمات والروابط العامة

تم فتح **كل الخدمات الثماني عشرة** في متصفح فعلي على النسخة المحلية. تحققت الجولة من أن كل مسار يعرض العنوان الصحيح، ولا ينتقل إلى صفحة مفقودة، ويعرض نموذجاً محلياً أو صفحة تحويل رسمية بحسب نوع الخدمة.

| نوع الخدمة | العدد | نتيجة الفحص |
|---|---:|---|
| خدمات محلية بنموذج خاص أو عام | 14 | نماذج ظاهرة، حقول موجودة، وزر إرسال مرتبط بمسار التقديم. |
| إجازة فتح محل المتخصصة | 1 | نموذج مفصل، مستند عقار، صورة واجهة، موقع، وتوثيق وجه. |
| خدمات وطنية خارجية | 3 | البطاقة الوطنية والجواز وإجازة السياقة تعرض متطلبات وروابط HTTPS رسمية خارجية؛ لا تنشئ المنصة طلباً محلياً موازياً. |
| خدمات مجدولة | 1 ضمن الخدمات المحلية | حجز الموعد يظهر كطلب للدائرة ويبقى بانتظار التأكيد البشري. |

كما اجتاز البحث والفلترة في الرئيسية، بما في ذلك العبارة الطبيعية **«إجازة محل»** التي تؤدي إلى خدمة **«إجازة فتح محل»**.

## حساب المواطن والتقديم والوجه والإشعارات

تم فحص المسار من زاوية زائر ومن زاوية حساب مواطن صناعي موثق. يسمح النظام بتصفح الاستمارة وملئها قبل الدخول، ثم يحتفظ بالمسودة وينقل الزائر إلى التسجيل عند محاولة الإرسال. عند عودة حساب موثق، تستعاد الخدمة والمسودة. لا ينشأ الطلب إلا بجلسة مواطن موثقة وفيديو وجه وموافقة صريحة على إرفاق الفيديو المشفر.

| الحالة | نتيجة الفحص |
|---|---|
| زائر يفتح نموذجاً محلياً | النموذج العام يظهر من دون قائمة حساب المواطن أو بيانات افتراضية. |
| زائر يحاول الإرسال | المسودة تحفظ ويتحول إلى `/onboarding` مع مسار العودة الصحيح. |
| حساب موثق يعود للخدمة | يستعاد مسار الخدمة وبيانات المسودة المخزنة. |
| فيديو الوجه | تظهر الكاميرا، إطار الوجه داخل المعاينة، عد تنازلي 7 ثوانٍ، شريط تقدم، وتعليمات متتابعة مثل «ابتسم للكاميرا». |
| الإشعارات | قائمة الهاتف وجرس الإشعارات يفتحان صفحة مستقلة؛ فتح الإشعار وتعليم الكل كمقروء يعملان في فحص الجلسة المعزول. |
| موقع المواطن | يطلب GPS عند موافقة المواطن، ويحفظ للمراجع المخول؛ لا تعود الإحداثيات في استجابة ملف المواطن. |

> توجيهات الابتسام وحركة الرأس داخل فيديو الوجه هي إرشادات لجودة اللقطة والتدقيق البشري. لا تمثل قرار هوية حكومياً آلياً أو مصادقة بيومترية نهائية.

## الصلاحيات والوسائط والأرشفة

تم تنفيذ فحوصات مستقلة لحقوق المواطن والموظف والمدير وغرفة العمليات. استخدمت بيانات تجريبية داخل قواعد مؤقتة فقط. تم التأكد من أن المواطن لا يستطيع فتح وسائط مراجعة الهوية الإدارية، وأن غرفة العمليات تبقى غير مخولة بقراءة مراجعات الهوية.

| الوظيفة | نتيجة الفحص |
|---|---|
| لوحة الموظف وروابط الأقسام | ناجح؛ روابط لوحة العمل والمعاملات والكشوفات والأرشيف والسجل تصل إلى علامات المحتوى الصحيحة. |
| لوحة المدير العام والدوائر | ناجح؛ الوصول غير المسجل مرفوض، وتحديث متطلبات خدمة في قاعدة الاختبار يظهر في واجهة الخدمة العامة. |
| غرفة العمليات | ناجح؛ الجلسة المؤقتة المخولة تقرأ الإحصاءات والتنبيهات، ومحاولة الوصول لمراجعات الهوية ترجع `401`. |
| مرفقات الهوية | ناجح؛ OCR محلي لمستند صناعي، حفظ مشفر، احتفاظ بموافقة صريحة، وعدم كشف الموقع للمواطن. |
| معاملات الخدمات | ناجح؛ رفض واضح عند غياب عقد الإيجار أو رفع ملف غير آمن، مع شرط فيديو الوجه وموافقته. |
| PDF وQR | ناجح؛ طلب خدمة وطلب إجازة محل صناعيان أُقرا، وولّد كل منهما PDF مؤرشفاً؛ يستطيع المواطن فتح الأصل، بينما رابط التحقق العام يعرض الوثيقة الأصلية المرتبطة بسجل التحقق. |

## حماية الإنتاج

فحص الإنتاج لم يستخدم تسجيل دخول أو رموز وصول. تحققت فقط من حدود الوصول العامة والردود الآمنة.

| الضابط | نتيجة الفحص |
|---|---|
| HTTPS والصحة | واجهة الصحة رجعت `200`. |
| رؤوس الحماية | ظهرت سياسة محتوى مقيدة، و`HSTS`، و`nosniff`، وسياسة مرجع صارمة. |
| CORS | مصدر تجريبي غير موثوق لم يتلق رأس سماح. |
| عزل نقاط الحساسة | نقاط إشعارات المواطن، أرشيف PDF، مراجعات الهوية، كاميرات العمليات، ولوحة الدوائر كلها رجعت `401` بلا جلسة. |

## حدود الفحص وخطة المتابعة

لم أرسل رمز OTP حقيقياً ولم أستخدم كاميرا أو GPS فعليين من هاتف حقيقي، كي لا تُستهلك رسائل أو تُرفع بيانات مواطن. بدلاً من ذلك تم اختبار المسارات البرمجية بكاميرا متصفح محاكية وبيانات صناعية، بينما يبقى اختبار إذن كاميرا الهاتف وOTP الحقيقي خطوة قبول ميداني تتطلب هاتفاً ورقم هاتف مصرحاً به.

لا توجد ملاحظة وظيفية مانعة من نتائج الفحص الحالية. توجد فقط تحذيرات تطوير غير مانعة تتعلق بتحسين بنية تأثيرات React وحجم حزمة JavaScript، ولا تمنع تشغيل المنصة أو أي مسار تم فحصه. نُشرت تحسينات شاشة فيديو الوجه وسكربتات الجودة التي تطابق شرط الفيديو والموافقة وحماية الموقع، وتحققت الحزمة المنشورة في الإنتاج بعد الدفع.

## التوصية

تم نشر تحسين شاشة تصوير الوجه والتحقق من إنتاجه. يبقى اختبار قبول ميداني واحد مستحسن لاحقاً: تشغيل إذن الكاميرا وGPS وإرسال OTP حقيقي من هاتف مصرح به، لأن هذا لم يُنفذ في الفحص الآلي لحماية بيانات المواطنين وتجنب استهلاك الرسائل.
