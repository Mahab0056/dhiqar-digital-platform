# متطلبات دليل خدمات ذي قار الحكومي

**المصدر الداخلي للمتطلبات:** `Pasted_content_02.txt`، مقدّم من المستخدم في 2026-08-27.  
**الغرض:** تحويل منصة ذي قار الرقمية من قائمة خدمات إلى دليل موحد يقود المواطن حسب حاجته أو حسب الجهة المسؤولة، من دون عرض تبعية إدارية خاطئة أو اختراع شروط ورسوم أو ربط غير موجود.

## قواعد التنفيذ الملزمة

| القاعدة | تطبيقها في المنصة |
|---|---|
| الوصول حسب الحاجة أو الجهة | يوفر الدليل بحثاً باللغة الطبيعية، وتصنيفات حسب المجال، وقائمة حسب الجهة. |
| تصنيف الجهة الصحيح | تستخدم السجلات `LOCAL_GOVERNMENT` أو `FEDERAL_GOVERNMENT` أو `INDEPENDENT_AUTHORITY` أو `PUBLIC_SERVICE_ENTITY`، مع الاحتفاظ بالجهة الأم. |
| التوثيق قبل الادعاء | يظهر فقط ما هو موثق، وأي خدمة غير مكتملة التفاصيل تسجل بصيغة مسودة معلوماتية أو انتظار ربط رسمي. |
| GIS | لا تسجل إحداثيات إلا لمنشأة محددة ذات مصدر موثوق؛ لا تستخدم إحداثيات تقريبية. |
| الرسوم والمتطلبات | لا تنشر للمواطن ما لم يوجد مصدر رسمي. تستعمل حالة «بانتظار اعتماد بيانات الخدمة» عند عدم التوثيق. |
| الرقمنة الجزئية | تصنف الخدمات إلى `FULLY_DIGITAL` أو `PARTIALLY_DIGITAL` أو `INFORMATION_ONLY` أو `EXTERNAL_INTEGRATION` وتوضح الخطوة الحضورية عند الحاجة. |
| الأمن والبيانات | لا تعرض ملكية عقار أو مرور أو صحة أو ضرائب أو بث كاميرات أو بيانات حساسة بلا تكامل وصلاحيات وتفويض رسمي. |
| الطوارئ | توجّه مخاطر الدفاع المدني والشرطة والكهرباء إلى القنوات الرسمية؛ لا تعالج كنموذج شكوى عادي. |

## مسارات الجهات والخدمات المطلوبة

الملف يطلب تغطية ديوان المحافظة والوحدات الإدارية والبلديات والماء والمجاري والطرق والتخطيط والصحة والتربية والتعليم العالي والزراعة والموارد المائية والبيئة والاستثمار والعمل والشباب والكهرباء والمرور والبطاقة الوطنية والجوازات والإقامة والدفاع المدني والشرطة والتسجيل العقاري والكاتب العدل والضرائب والتقاعد وعقارات الدولة ومؤسسة الشهداء والسجناء السياسيين والقطاع النفطي والاتصالات والبريد والسياحة والآثار.

يُبنى التنفيذ على مستويين. المستوى الأول هو الخدمات المحلية الحالية القابلة لاستلام نموذج ومراجعته داخل المنصة. والمستوى الثاني هو الجهات الاتحادية أو الخدمات التي لا تتوافر لها واجهة تكامل مصرح بها، وتظهر كدليل رسمي أو تحويل خارجي فقط إلى أن تُوثق واجهة ربط أو خدمة إلكترونية خاصة بالجهة.

## حالة رمز غرفة العمليات

وافَق المستخدم صراحة على رمز مؤقت من أربع خانات. تم تعديل الواجهة والخادم محلياً ليقبلا رمزاً رقمياً من أربع خانات مع بقاء محدد المحاولات والجلسة المحمية ودور القراءة التشغيلي المقيد. يجب تدوير الرمز إلى قيمة قوية قبل استخدام غرفة العمليات ببيانات حقيقية.

## حدود الإصدار التالي

- لا تضاف شعارات أي جهة إلا من مصدر الجهة أو بوابة حكومية موثقة، مع رابط مصدر وحالة تحقق.
- لا تضاف نقطة GIS أو رقم هاتف أو ساعات عمل إلا عندما تتوفر مصادر قابلة للإسناد.
- لا يتم تفعيل دفع أو إصدار وثيقة أو فحص أهلية أو تتبع معاملة وطنية أو بث كاميرا قبل تكامل الجهة المالكة وتفويضها.
- توجيه الدائرة حسب حدود إدارية وGIS يحتاج طبقة حدود إدارية موثقة وبيانات موقع للمواطن؛ إلى ذلك الحين تظهر الجهة المسؤولة المقترحة بصراحة على أنها «تحتاج تحديد الموقع أو اعتماد جهة الاختصاص».


## سجل تطبيق رمز غرفة العمليات

في 2026-08-27 أُدخل الرمز المؤقت الذي حدده المستخدم مباشرة في متغير خدمة Railway وتم إرسال التغيير للتطبيق. لا يحتوي هذا المستند ولا المستودع على قيمة الرمز. قبل الاعتماد التشغيلي أو ربط بيانات حقيقية، يجب استبدال الرمز المؤقت برمز قوي فريد.


## اتجاه بصري إضافي من الملف الثالث

الملف `Pasted_content_03.txt` يطلب إعادة تصميم بصرياً جذرياً للواجهة مع منع تغيير الـ Backend أو قاعدة البيانات أو APIs أو الميزات والخدمات أو سير المعاملة. الاتجاه المطلوب هو **الحضارة السومرية × الحكومة الرقمية**: طبقات هادئة، هوية أخضر/نحاسي قائمة، خلفيات off-white، مقاطع داكنة محدودة، خطوط رفيعة، وعمق بصري مضبوط بلا مظهر قالب حكومي عام أو Glassmorphism مبالغ.

تحدد المتطلبات للصفحة الرئيسية هيرو بارتفاع قريب من الشاشة الكاملة. الخلفية تعتمد خريطة ذي قار تجريدية بحدود رفيعة ونقاط للدوائر والمدن والخدمات وروابط رقمية، مع هندسة زقورة أور كملمح معماري لا كصورة سياحية. التفاعل الرئيسي هو بحث حكومي كبير بعنوان «شنو تحتاج؟» بأمثلة عراقية تتغير بهدوء واقتراحات تقود إلى الخدمة والجهة المختصة. كما تطلب قصة تمرير تحوّل الخريطة إلى شبكة خدمات وتعرض حركة طلب المواطن عبر التدقيق والموافقة إلى وثيقة QR، ثم مستكشف خدمات تفاعلي ومقطع خريطة للدوائر.

لن تغيّر هذه المتطلبات أي منطق تشغيلي أو مصدر بيانات؛ ويجب أن تستخدم الخريطة الحالية والنقاط المتحققة فقط، وأن يبقى أي شعار أو خدمة أو جهة أو صورة خاضعاً للمصدر والتفويض المناسبين.


## مراجعة أصول الهيرو المحلية

جرت معاينة صورتين محفوظتين ضمن المشروع. ملف `ur-heritage-hero.jpg` يتضمن شعاراً وعناصر مستقبلية مدمجة، لذلك لا يصلح كصورة فوتوغرافية هادئة مستقلة للهيرو. وملف `marshes-future.jpg` يحمل نصاً وعناصر عرض مدمجة، ولذلك لا يُستخدم كخلفية هيرو حتى لا يتكرر النص أو يوحي بأن التصميم مصدر مستقل. سيُعتمد فقط على صور الموقع الفوتوغرافية غير المضمنة بالنص أو على طبقات رسومية CSS فوق مصدر محدد.


تمت معاينة صورتين إضافيتين من أرشيف الأخبار المحلي. `public/news/dhiqar-governorate.jpg` يظهر واجهة ديوان محافظة ذي قار بوضوح، ولذلك يصلح صورة محلية لطبقة جانبية أو بطاقة ضمن الهيرو. أما `public/news/souq-shuyoukh-project.jpg` فيظهر متابعة مشروع ميداني في سوق الشيوخ؛ يصلح كمشهد تشغيلي ثانوي ولا يستخدم كصورة رئيسية لأنه يحتوي أشخاصاً في موقع عمل. ستُستخدم الصور الموجودة من المشروع فقط مع تسميات مصدرها، وستكون الحركة CSS خفيفة بلا ادعاء بث حي أو بيانات مباشرة.
