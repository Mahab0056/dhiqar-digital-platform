# فحص اعتماد المعاملات القديمة وتوثيق الوجه

**التاريخ:** 2026-08-28  
**النطاق:** معالجة معاملة موجودة بلا مرفقات توثيق، إجراءات الموظف، رفع فيديو الوجه، وإصدار الوثيقة.

## سبب المشكلة

المعاملة الظاهرة كانت بلا مرفقات محفوظة. هذا يطابق المعاملات التي أُنشئت قبل إلزام فيديو توثيق الوجه أو التي لم يصل رفع مرفقها إلى الخادم. كما أن معالج أزرار لوحة الموظف لم يكن يعرض خطأ الطلب بطريقة واضحة؛ فإذا أخفق الإجراء بقيت حالة الانشغال ظاهرة وكأن الزر لا يستجيب.

## التعديل

| المجال | السلوك بعد الإصلاح |
|---|---|
| لوحة الموظف | تظهر رسالة صريحة توضح أن الاعتماد متوقف لأن فيديو الوجه غير محفوظ؛ لا يبقى الزر معطلاً بلا سبب. |
| طلب قديم بلا فيديو | زر «طلب استكمال التوثيق» يرسل إشعاراً للمواطن ويحوّل الحالة إلى `ACTION_REQUIRED`. |
| حساب المواطن | يفتح رابط المعاملة قسم تسجيل فيديو وجه لمدة 7 ثوانٍ بالكاميرا الأمامية، مع الإطار والعد والتعليمات. |
| رفع الفيديو | يحفظ الفيديو كمرفق مشفر من نوع `FACE_VIDEO` ثم يعيد المعاملة إلى الموظف بحالة `UNDER_REVIEW`. |
| الاعتماد الخادمي | يرفض الخادم الاعتماد بوضوح (`409`) إذا لم يجد فيديو وجه صالحاً، حتى عند تجاوز الواجهة. |
| أخطاء الموظف | أي فشل في الطلب أو الاعتماد يظهر في لوحة المراجعة وينهي حالة الانشغال، كي تبقى الأزرار قابلة للتجربة ثانية. |

## تحقق منفذ

| الاختبار | النتيجة |
|---|---|
| `qa_legacy_application_face_verification.ts` | نجح: منع اعتماد الطلب القديم، طلب فيديو الوجه، رفعه كمرفق مشفر، ثم اعتماد الطلب وإصدار رقم وثيقة ومعرّف تحقق. |
| `qa_employee_legacy_verification_ui.mjs` | نجح: ظهرت رسالة السبب، زُر الاعتماد أصبح معطلاً بعنوان مفهوم، وزر طلب الاستكمال نفذ الإجراء. |
| `pnpm build` | نجح دون أخطاء TypeScript. |
| `qa_service_route_integrity.ts` | نجح لجميع مسارات الخدمات الثماني عشرة. |
| `qa_home_login_integrity.sh` | نجح؛ التغيير لا يكسر الصفحة الرئيسية أو الدخول. |

> لا يحق للموظف اعتماد معاملة بلا فيديو وجه بعد هذا التعديل. المقصود حماية المعاملة وليس منعها نهائياً؛ يطلب الموظف الاستكمال، يرسل المواطن الفيديو، ثم يعود الطلب تلقائياً إلى التدقيق.
