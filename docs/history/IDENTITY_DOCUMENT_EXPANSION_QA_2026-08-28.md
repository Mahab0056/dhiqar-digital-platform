# تحقق توسعة مستندات الهوية — 2026-08-28

## ما تم اختباره

تم تشغيل خادم اختبار منفصل مع قاعدة SQLite ووسائط مشفرة مؤقتة. استُخدمت ملفات JPEG وWebM صناعية بلا أسماء أو أرقام أو صور أشخاص حقيقيين. أثبت الاختبار أن مسار **جواز السفر** يقبل صفحة البيانات وفيديو الوجه من دون إلزام ظهر وثيقة، ويحفظ الوسيطين بسياسة `RETAINED_WITH_CONSENT`.

بعد قرار موافقة من جلسة مدير عام اختبارية، بقيت الملفات موجودة ومشفرة ولم يحذفها مسار المراجعة. كما أعاد مسار قراءة الوسيط الإداري `401` لجلسة المواطن، وحُفظ موقع المواطن بعد موافقة صريحة فقط. نتيجة الاختبار: `identity_document_expansion_qa=pass`.

## قيود التحليل الآلي

عقد استخراج البيانات والمطابقة المساعدة جاهز، لكنه لا يتصل حالياً بمزود OCR أو مطابقة وجه مصرح في إنتاج Railway. عند غياب متغيرات المزود، يعيد المسار حالة `PROVIDER_UNAVAILABLE` وحقولاً فارغة، ولا يخمن الاسم أو رقم الوثيقة أو صورة الملف. تظل مراجعة الموظف المخول مطلوبة لكل مستند.

## متغيرات الربط المطلوبة لاحقاً

لا يعمل الاستخراج أو قص صورة الملف أو نتيجة المطابقة المساعدة إلا بعد توفير مزود مؤسسي مصرح له ومعالجة المتغيرين التاليين في Railway:

| المتغير | الغرض |
|---|---|
| `IDENTITY_DOCUMENT_AI_ENDPOINT` | عنوان HTTPS لخدمة OCR/تحليل مستندات ومطابقة مساعدة معتمدة. |
| `IDENTITY_DOCUMENT_AI_KEY` | مفتاح مزود التحليل؛ يبقى داخل بيئة الخادم فقط ولا يدخل المستودع أو المتصفح. |

> لا تعني النتيجة الآلية اعتماداً حكومياً للهوية أو تحققاً بيومترياً نهائياً. لا تنشر المنصة هذا الوصف ولا تغيّر حالة المواطن إلى معتمد إلا بقرار مراجعة مخول.
