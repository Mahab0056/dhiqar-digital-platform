# تفعيل دخول الموظفين بحساب Google وبرمز البريد الإلكتروني

هذا الدليل لمالك المنصة. بعد إكماله يظهر في صفحة دخول الموظفين (`/staff/login`) زرّ **«الدخول بحساب Google»** وتبويب **«رمز على البريد الإلكتروني»** إضافةً إلى اسم المستخدم وكلمة المرور. يشمل ذلك كل الأدوار: موظف المعاملات، مراجع الهوية، **غرفة العمليات**، ومدير النظام.

> **قاعدة الأمان:** لا يوجد تسجيل ذاتي. Google أو رمز البريد يُثبتان ملكية البريد فقط؛ الدخول لا يتم إلا إذا كان هذا البريد مسجّلاً مسبقاً على حساب موظف **فعّال** من قِبل مدير النظام. الحساب المعطّل أو المقفل مؤقتاً يُرفض، ومن فعّل المصادقة الثنائية (TOTP) يُطلب منه الرمز بعد Google أو البريد كالمعتاد.

---

## الجزء الأول: Google

### 1) إنشاء مشروع في Google Cloud

1. ادخل إلى <https://console.cloud.google.com/> بحساب Google الخاص بالجهة (يُفضَّل حساب مؤسسي لا شخصي).
2. من القائمة العلوية اختر **Select a project ← New Project**.
3. الاسم: `Thi Qar Digital` ثم **Create**، وتأكد أن المشروع الجديد هو المحدد.

### 2) شاشة الموافقة (OAuth consent screen)

1. القائمة ← **APIs & Services ← OAuth consent screen** (في الواجهة الجديدة: **Google Auth Platform ← Branding**).
2. نوع المستخدمين (Audience):
   - **Internal**: إذا كان للجهة Google Workspace وكل الموظفين ببريد النطاق نفسه (مثل `@thi-qar.com`). هذا الأفضل والأكثر أماناً.
   - **External**: إذا كان الموظفون يستخدمون Gmail عادياً. بعد الإعداد اضغط **Publish app** (لا تحتاج مراجعة من Google لأن الصلاحيات المطلوبة أساسية فقط: `openid` و`email` و`profile`).
3. املأ: اسم التطبيق `ذي قار الرقمية`، بريد الدعم، الشعار (اختياري)، والنطاق المصرّح به `thi-qar.com`.
4. في **Scopes / Data access** أضف فقط: `openid`، `.../auth/userinfo.email`، `.../auth/userinfo.profile`.

### 3) إنشاء OAuth Client

1. **APIs & Services ← Credentials ← Create credentials ← OAuth client ID** (أو **Clients ← Create client**).
2. **Application type: Web application**، الاسم: `Thi Qar staff login`.
3. **Authorized JavaScript origins** (اختياري):
   - `https://thi-qar.com`
   - `https://www.thi-qar.com`
4. **Authorized redirect URIs** (إلزامي، انسخها حرفياً):
   - `https://thi-qar.com/api/auth/staff/google/callback`
   - `https://www.thi-qar.com/api/auth/staff/google/callback`
5. **Create**، ثم انسخ **Client ID** و**Client secret** (السر لا يُشارك مع أحد ولا يوضع في الكود).

### 4) ضبط المتغيرات في Railway

في Railway ← المشروع ← خدمة المنصة ← **Variables** أضف:

| المتغير                  | القيمة                                    | ملاحظة                                                                                   |
| ------------------------ | ----------------------------------------- | ---------------------------------------------------------------------------------------- |
| `GOOGLE_CLIENT_ID`       | `xxxxxxxx.apps.googleusercontent.com`     | من الخطوة 3                                                                              |
| `GOOGLE_CLIENT_SECRET`   | `GOCSPX-...`                              | من الخطوة 3                                                                              |
| `PUBLIC_BASE_URL`        | `https://thi-qar.com`                     | موجود غالباً؛ يُستخدم إن جاء الطلب من نطاق غير معروف                                     |
| `GOOGLE_ALLOWED_DOMAINS` | `thi-qar.com` (اختياري)                   | قائمة نطاقات مفصولة بفواصل. إن ضُبطت يُرفض أي بريد خارجها حتى لو كان مرتبطاً بحساب موظف |

بعد الحفظ يعيد Railway النشر تلقائياً، ويظهر زر Google في صفحة الدخول. إن لم تُضبط المتغيرات يبقى الزر مخفياً.

## الجزء الثاني: رمز البريد الإلكتروني (عبر Resend)

### 1) حساب Resend وتوثيق النطاق

1. أنشئ حساباً في <https://resend.com/>.
2. **Domains ← Add Domain** واكتب `thi-qar.com` (المنطقة: الأقرب، مثل `eu-west-1`).
3. سيعرض Resend سجلات DNS (عادةً **TXT** لـ SPF و**TXT** لـ DKIM باسم `resend._domainkey`، وقد يطلب **MX** لنطاق فرعي مثل `send`). أضفها كما هي عند مزوّد DNS للنطاق (Cloudflare أو غيره).
4. يُنصح أيضاً بسجل DMARC إن لم يكن موجوداً:
   `_dmarc.thi-qar.com  TXT  "v=DMARC1; p=none; rua=mailto:dmarc@thi-qar.com"`
5. انتظر حتى تصبح حالة النطاق **Verified** (دقائق إلى ساعات).

### 2) مفتاح API والمتغيرات

1. **API Keys ← Create API Key**، الصلاحية: **Sending access** فقط، النطاق: `thi-qar.com`.
2. في Railway ← **Variables**:

| المتغير          | القيمة                                    |
| ---------------- | ----------------------------------------- |
| `RESEND_API_KEY` | `re_...`                                  |
| `MAIL_FROM`      | `ذي قار الرقمية <no-reply@thi-qar.com>`   |

بعد إعادة النشر يظهر تبويب «رمز على البريد الإلكتروني». **في بيئة الإنتاج، إن لم يُضبط مزوّد بريد يبقى التبويب مخفياً**. (في التطوير المحلي فقط يُطبع الرمز في سجل الخادم بدلاً من إرساله.)

> ملاحظة: متغيرات SMTP العامة (`SMTP_HOST`…) غير مستخدمة حالياً لأن المنصة لا تتضمن مكتبة SMTP؛ Resend هو المزوّد المدعوم.

### كيف يعمل الرمز

- رمز من 6 أرقام صالح **10 دقائق**، يُستخدم **مرة واحدة**، و**5 محاولات** كحد أقصى؛ طلب رمز جديد يُلغي السابق.
- إعادة الإرسال بعد 60 ثانية، و5 طلبات في الساعة لكل بريد، و20 طلباً كل 15 دقيقة لكل عنوان IP.
- الرد على طلب الرمز واحد دائماً سواء كان البريد مرتبطاً بحساب أم لا (لا يمكن معرفة من هم الموظفون).
- الرموز الخاطئة تُحتسب ضمن عدّاد القفل نفسه لكلمة المرور (5 محاولات ← قفل 15 دقيقة).
- الرمز يُخزَّن مشفّراً بـ HMAC ولا يظهر في سجل التدقيق.

## الجزء الثالث: ربط بريد كل موظف (إلزامي)

1. ادخل كمدير نظام ← **لوحة المدير ← حسابات الموظفين**.
2. عند إنشاء حساب جديد: املأ حقل **«البريد الإلكتروني (اختياري)»**.
3. لحساب موجود: في عمود **«بريد الدخول»** اضغط أيقونة القلم ✎، اكتب البريد ثم **حفظ**. لإلغاء الربط امسح الحقل واحفظ.
4. اربط بريدك أنت أيضاً (حساب مدير النظام) بالطريقة نفسها.
5. البريد فريد: لا يمكن ربط البريد نفسه بحسابين.

بعدها يستطيع الموظف من `/staff/login` (وكذلك روابط `/operations/login` و`/super-admin/login` التي تحوّل إليها):

- الضغط على **«الدخول بحساب Google»** واختيار حساب Google بالبريد نفسه، أو
- اختيار **«رمز على البريد الإلكتروني»** ← كتابة البريد ← إدخال الرمز الواصل.

ثم يُحوَّل تلقائياً إلى بوابته: غرفة العمليات ← `/operations`، مدير النظام ← `/super-admin`، باقي الموظفين ← `/employee`.

## رسائل الخطأ التي قد تظهر

| الرسالة                                  | السبب والحل                                                                      |
| ---------------------------------------- | -------------------------------------------------------------------------------- |
| لا يوجد حساب موظف مرتبط بهذا البريد     | اربط البريد بحساب الموظف من «حسابات الموظفين»                                   |
| هذا النطاق غير مسموح به                 | البريد خارج `GOOGLE_ALLOWED_DOMAINS`                                             |
| هذا الحساب معطّل / مقفل مؤقتاً          | فعّل الحساب أو انتظر 15 دقيقة                                                    |
| انتهت صلاحية طلب الدخول بحساب Google    | مرت أكثر من 10 دقائق أو فُتح الرابط في متصفح آخر؛ ابدأ من جديد                    |
| تعذر إكمال الدخول بحساب Google          | تحقق من `GOOGLE_CLIENT_SECRET` ومن مطابقة Redirect URI حرفياً في Google Cloud    |

كل محاولة دخول ناجحة أو فاشلة بـ Google أو بالبريد تُسجَّل في **سجل التدقيق** (`STAFF_GOOGLE_LOGIN_*` و`STAFF_EMAIL_*` و`STAFF_SESSION_CREATED`).
